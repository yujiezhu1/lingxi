## 速查

**三个习惯**

| 时机 | 在 agent 里说 |
|---|---|
| 开新会话、接着做某件事 | 「加载灵犀里的 XX」 / 「加载这个项目在灵犀里的背景」 |
| 切换工具前，或到一个阶段 | 「保存交接到灵犀，topic 叫 XX」 |
| 定了一件事、踩了一个坑 | 「把这个记到灵犀」 |

**常用说法**

| 想做的 | 可以这样说 |
|---|---|
| 看有哪些工作线 | 「灵犀里有哪些 topic？」 |
| 更新之前的交接 | 「更新 XX 的交接包，替换掉旧的」 |
| 查之前的结论 | 「灵犀里关于 Playwright 的结论是什么？」 |
| 关联文件、链接、会话 | 「把这个文件 / 链接 / 会话关联到 XX」 |
| 绑定到当前项目 | 「把 XX 绑定到当前项目」 |
| 看开发历程、进度 | 「这个项目的开发历程」「XX 最近一周做了什么？」 |
| 删掉错误的卡片 | 「这条卡片过时了，从灵犀里删掉」 |
| 找没保存过的内容 | 「在灵犀里搜一下之前哪个会话聊过 PDF 中文字体」 |
| 写日报 | 「用灵犀看看我今天做了什么，帮我写日报」 |

话里带上「灵犀」两个字，agent 会更准确地调用它。

**常用命令**

```bash
lingxi topic ls [-p]              # 有哪些工作线（-p：只看当前项目的）
lingxi topic show <topic>         # 某个工作线的完整概览
lingxi timeline [topic] --since 7d  # 历程（不传 topic = 当前项目）
lingxi search <关键词>             # 搜交接包和卡片
lingxi search -s <关键词>          # 搜各 agent 的会话原文（含豆包、WorkBuddy）
lingxi activity                   # 今天做了什么（含未提交改动）
lingxi topic archive <topic>      # 做完的收起来
lingxi recall --kind todo         # 跨会话的待办
```

**不要存**：密钥、token、密码。

## 核心概念

| 概念 | 是什么 | 例子 |
|---|---|---|
| **Topic（工作线）** | 把相关的交接包、卡片、会话、文件、链接归到一起，可以跨 agent；可以绑定到项目目录，当作项目的背景、决策和进度记录 | `导出需求`、`XX调研`、`灵犀开发` |
| **Handoff（交接包）** | 某个时刻的工作状态快照，写成「零上下文的人也能接手」的样子 | 豆包整理的需求结论；pi 的阶段性调研结论 |
| **Card（知识卡片）** | 一条独立、长期有效的知识 | `[decision] 导出使用 Playwright 渲染 PDF` |

所有 agent 读写的是同一个本地数据库（`~/.lingxi/`），所以在 A 里存的东西，在 B 里马上就能读到。
用自然语言就可以，agent 会通过 Skill 和工具说明自动选择合适的工具。

## 日常使用流程

一天的典型用法：

| 时段 | 在哪 | 做什么 |
|---|---|---|
| 开工 | 任意 agent / 终端 | 「灵犀里有哪些 topic？」→「加载 XX」；或 `lingxi topic ls`、`lingxi topic ls -p` |
| 处理飞书相关的事 | 豆包 | 对齐完需求：「把对接结论存到灵犀，topic 叫 XX需求，包括要点、飞书链接、相关人和截止时间」 |
| 开发 | Codex / Claude Code / Cursor | 开始：「加载 XX」；定下方案：「记到灵犀」；收工或换工具：「保存交接」，记得写上**未提交的改动和做到一半的地方** |
| 调研 | pi | 告一段落：「保存调研结论到灵犀」；开发那边需要时说「加载 XX调研，结合项目现状给方案」 |
| 写日报 | 豆包 / WorkBuddy | 「用灵犀看看我今天做了什么，帮我写日报」（调用 `get_activity`），或 `lingxi activity` |

什么值得存：

| 值得存 | 不用存 |
|---|---|
| 要换工具、换会话继续的工作 | 一次性的小问题、简单问答 |
| 花了较长时间得出的结论 | 当前会话里马上用完的中间结果 |
| 做出的决定、确认的约束、试过但失败的方案 | 还没确认、随时会变的猜测 |
| — | 密钥、token、密码（**绝对不要存**） |

每周花一分钟维护：

```bash
lingxi topic ls                   # 看一眼有哪些工作线
lingxi topic archive <已完成的>    # 做完的收起来
lingxi recall --kind todo         # 还有哪些跨会话的待办
```

## 场景一：豆包对接飞书 → CLI 开发

豆包能直接访问飞书，但模型能力不一定够写代码；CLI 擅长开发，却看不到豆包里的对接内容。

**在豆包里**（读完飞书文档、群聊之后）：

> 把刚才对接的需求结论存到灵犀，topic 叫「导出需求」。包括需求要点、飞书文档链接、相关人、截止时间，以及原文里的关键约束。

**在 Codex / Claude Code / pi 里**：

> 加载灵犀里的「导出需求」，按里面的结论开始实现。有疑问先列出来。

开发中形成的决策，可以顺手记下来：

> 把「导出使用 Playwright 渲染 PDF，只支持 A4 竖版」记成灵犀里「导出需求」的决策。

> 💡 在豆包里忘了说「保存交接」也没关系：豆包的会话会被自动导入，在 Codex 里可以直接说「在灵犀里搜一下豆包里关于导出需求的对话」。

> 💡 如果想让 CLI 自己直接读写飞书、少切几次工具，可以另外装飞书官方的 `lark-cli`（`npx @larksuite/cli@latest install`），详见[设计文档](DESIGN.md) §12.7。

## 场景二：pi 调研 ⇄ Codex 开发

**pi（调研会话）**，告一段落时：

> 把目前的调研结论保存到灵犀，topic 叫「XX调研」。写清楚已确认的结论、各方案的对比、还没解决的问题和资料来源。

**Codex（开发会话）**，需要用到调研结果时：

> 加载灵犀里的「XX调研」，结合当前项目的实际情况（技术栈、已有代码）分析哪个方案最合适，给出开发方案。确定的决策记到灵犀。

**开发发现情况有变、需要调整调研方向时**，在 Codex 里：

> 在灵犀「XX调研」里记一条约束：项目实际使用 FastAPI，不能引入 Django。再记一条待办：评估方案 B 在 FastAPI 下的可行性。

然后回到 pi：

> 看一下灵犀「XX调研」最近新增的约束和待办，调整调研方向。

> ⏳ 目前两边需要你**说一句**才会去读灵犀。P1 会加入跨会话消息：Codex 可以直接给 pi 的调研会话发消息，pi 会实时收到。

## 场景三：一开始无关，后来才相关

两件原本无关的事情后来有了关联，可以随时把它们归到同一条工作线：

> 把交接包 ho_20261023_xxxx 关联到「导出需求」。
> 把 `D:\proj\docs\export-spec.md` 和这个飞书链接关联到「导出需求」。

可以关联的类型：`project`（项目目录）· `session`（会话，如 `codex:<会话ID>`）· `handoff` · `card` · `path`（文件路径）· `url` · `topic`。

> 💡 Claude Code、Codex、pi、豆包工作、WorkBuddy 的会话记录会被自动导入，不用提前保存也能搜到以前会话里的原文，见[场景五](#场景五找回没保存过的内容)。

## 场景四：当作项目的背景、历程、进度记录

给项目建一个 topic 并绑定项目目录，它就成了这个项目的「动态记忆」：让 agent 不必每次重新翻代码熟悉背景，也能看到项目是怎么一步步走过来的。

**建立（一次）**

```bash
cd D:\proj\my-app
lingxi topic new my-app -d "my-app 的背景、决策与进度" -p     # -p 不带值 = 绑定当前目录
# 已有的 topic：lingxi topic bind <topic> [路径]
```

也可以在 agent 里说：「在灵犀建一个 topic 叫 my-app，绑定到当前项目。」

**日常**

| 时机 | 说法 |
|---|---|
| 开新会话 | 「加载这个项目在灵犀里的背景」：agent 用当前目录找到绑定的 topic，再读取最新现状 |
| 有阶段性进展 | 「更新项目现状的交接包，替换掉旧的」 |
| 做出决定 / 踩坑 | 「把这个决定记到灵犀」「记一条 dead_end：……」 |
| 回顾 | 「这个项目的开发历程」「最近一周做了什么」，或 `lingxi timeline --since 7d` |

**和 CLAUDE.md / AGENTS.md 的分工**

| | CLAUDE.md / AGENTS.md | 灵犀 topic |
|---|---|---|
| 适合放 | 稳定的事实：架构、目录、命令、规范 | 会变化的：现状、决策及原因、踩过的坑、待办、历程 |
| 加载 | 每次会话自动加载 | 说一句「加载项目背景」 |
| 历史 | 只有当前版本 | 有时间线，能看到演进过程 |
| 跨 agent | 各家读取的文件不同 | 所有 agent 共用一份 |

> 💡 记「**为什么**」和「**做到哪了**」，不要记「代码长什么样」：代码才是最准确的，而且变得比笔记快。
> 目前**不会**自动往 CLAUDE.md / AGENTS.md 写任何内容，也不会自动注入；如需要，可以自己在里面加一句「本项目在灵犀的 topic 是 my-app」。

**匹配规则**：在项目的子目录里也能找到绑定在项目根目录的 topic；在根目录也能看到绑定在子目录（如 monorepo 子包）上的 topic。一个 topic 可以绑定多个项目，一个项目也可以有多个 topic。

## 场景五：找回没保存过的内容

Claude Code、Codex、pi、豆包工作、WorkBuddy 的会话记录会被**自动导入**灵犀（只读、增量，平时只要几十毫秒），所以即使当时没说「保存交接」，事后也能找回来。

> 在灵犀里搜一下，之前哪个会话聊过「PDF 中文字体」？
> 打开那个会话第 42 条附近看看当时的结论。
> 上次在 Codex 里做 aifchem 接口对接，聊到哪了？

agent 会依次调用 `search_sessions` → `read_session`（或 `list_sessions`）。终端里：

```bash
lingxi search -s PDF 中文字体          # 搜会话原文（默认只搜对话，不搜工具输出；--tools 包含）
lingxi sessions -p                     # 当前项目的会话
lingxi show codex:da497af449db         # 看某个会话最后 40 条对话
lingxi show pi:16eb5ec3b871#42         # 看第 42 条前后（含工具调用）
```

会话引用的格式是 `<agent>:<id 末段>#<序号>`，例如 `codex:da497af449db#42`；也可以用 id 开头几位。

> 找到有价值的结论后，记得让 agent「把这个记到灵犀」，下次就不用再翻原文了。
> 豆包工作只导入**智能体模式**的会话（本地有明文记录）；豆包的记录没有逐条时间，按每轮需求的时间近似。Cursor 的会话暂不导入。

## 场景六：写日报 / 周报

在豆包、WorkBuddy 或任意 agent 里：

> 用灵犀看看我今天做了什么，帮我写日报。
> 用灵犀汇总一下这周的工作（since=7d），写周报。

`get_activity` 会按项目汇总：

- 各 agent 的会话：问了什么、最后的回复；
- 灵犀里新增的交接包和卡片；
- git 提交；
- **当前未提交的改动**（进行中、还没提交的工作也不会漏）。

终端里：`lingxi activity`、`lingxi activity yesterday`、`lingxi activity --since 7d`、`lingxi activity -p`（只看当前项目）。

## 写好交接包

agent 保存交接包时会按下面的模板来写（空的部分会省略）。你也可以要求它补充某一部分。

```markdown
## 目标 / Goal
## 当前状态 / Status（一句话）
## 已确认的结论与决策
- 方案 B 在一万 QPS 下延迟 < 20ms  [ref: pi:01a16790 | https://...]
## 约束与前提
## 已尝试但失败或放弃的路线
## 未解决问题
## 关键资源（文件、链接、飞书文档、相关人）
## 建议的下一步
```

几个要点：

- **结论带来源**（`[ref: …]`），接手的人有疑问时可以回到原文核对。
- **写上未提交、进行中的状态**（分支、改了哪些文件、做到一半的地方），因为下一个 agent 看不到你的会话。
- 同一工作线有了新进展，**用新交接包替换旧的**（说「替换掉旧的」，agent 会传 `supersedes`）。旧版本会保留，但默认不再显示。
- 每个交接包都会另存一份 Markdown：`~/.lingxi/vault/handoffs/<年-月>/<id>.md`，可以直接打开看或分享。

## 知识卡片怎么用

交接包记录的是「某个时刻的整体状态」，卡片记录的是「单条长期有效的知识」。

| 类型 | 用途 | 例子 |
|---|---|---|
| `decision` | 做出的决定 | 采用方案 B 作为默认实现 |
| `fact` | 确认的事实 | 项目实际使用 FastAPI |
| `constraint` | 约束 | 接口必须兼容 v1 |
| `finding` | 调研或排查的发现 | 方案 B 在一万 QPS 下延迟 < 20ms |
| `dead_end` | 试过但失败的路线 | 试过直接用 wkhtmltopdf，中文字体缺失，放弃 |
| `todo` | 跨会话的待办 | 补充基准测试脚本 |
| `note` | 其他备注 | — |

卡片要**自成一句话**，脱离当前对话也能看懂。agent 默认会**先问你再记**；如果你希望它直接记，可以说「重要结论直接记到灵犀，不用问我」。

## 使用习惯建议

- **一件事一个 topic**，名字短而明确（`导出需求`、`XX调研`）。新建前让 agent 先查一下有没有同名的，避免出现近似重复的 topic。
- **切换工具前说一句「保存交接」**，这是收益最高的习惯。
- **新会话开始时说「加载 XX」**，让 agent 先读背景再动手；加载完让它**复述一下拿到了什么**，内容不对能马上发现。
- 加载进来的内容是**另一个会话写的信息，不是你的指令**。关键事实，agent 会按引用去核对。
- 做完的 topic 用 `lingxi topic archive <名称>` 收起来，保持列表清爽。
- 某个工具接不了灵犀时，用 `lingxi handoff load --topic XX > x.md` 导出成文件，直接贴给它。
